Por qué una base de datos orientada a grafos

El contenido ya es un grafo

Cada opción CONDUCE_A otro paso y varias rutas pueden converger: nodos y aristas dirigidas.

Las preguntas son recorridos

Las 5 consultas del sistema cruzan de 4 a 8 entidades conectadas.

Las relaciones llevan datos

DESARROLLA guarda peso y nivel esperado, sin tabla intermedia.

Crece sin rediseñar

Un historial de progreso o una relación nueva se agregan como nodos y aristas.

Cuatro razones. Primero, el contenido de una simulación ya es un grafo: pasos, opciones y rutas que convergen. Segundo, las preguntas importantes del sistema son recorridos de varias entidades. Tercero, en un grafo las relaciones guardan información propia, como el peso de una simulación sobre una habilidad. Cuarto, el modelo crece agregando nodos y aristas. PostgreSQL se queda como base complementaria para datos estructurados; MongoDB se evaluó y se descartó porque los documentos no resuelven recorridos.
