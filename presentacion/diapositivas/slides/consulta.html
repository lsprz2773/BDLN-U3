Una consulta, un recorrido

C-03 · ¿Qué decidió el usuario, qué pasó y qué retroalimentación recibió?

MATCH (u:Usuario)-[:REALIZA]->(i:Intento)
MATCH (i)-[:REGISTRA]->(r:Respuesta)
MATCH (r)-[:CORRESPONDE_A]->(p:Paso)
MATCH (r)-[:SELECCIONA]->(o:Opcion)
OPTIONAL MATCH (o)-[:GENERA]->(c:Consecuencia)
OPTIONAL MATCH (r)-[:GENERA]->(f:Retroalimentacion)
RETURN r.secuencia, p.titulo, o.descripcion, c, f

Ejemplo con la consulta C-03: reconstruir las decisiones de un usuario. En Neo4j se escribe como un patrón que recorre siete entidades, de usuario a retroalimentación. En una base relacional serían seis JOIN entre siete tablas. La propiedad secuencia ordena las decisiones del intento. En el entregable 1 están las cinco consultas escritas en Cypher y verificadas contra el modelo.
